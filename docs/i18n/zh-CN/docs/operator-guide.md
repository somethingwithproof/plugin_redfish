# Redfish 操作指南

本指南适用于里程碑 2 和 3 之后的 plugin_redfish 开发版，目前尚无带标签的发布版本。CI 在 PHP 8.2 至 8.5 上测试 Cacti 1.2.31 和当前 1.2.x 分支，包括插件安装和图表流程。这些任务使用测试 BMC 和 DMTF Redfish 模拟服务器，不能证明真实厂商或固件系列已通过验证。

<a id="before-installing"></a>
## 安装之前

- 使用 Cacti 1.2.31 或更高版本，以及 PHP 8.2 或更高版本。插件会明确拒绝在 PHP 8.2 以下安装或启用。
- 运行 Cacti 轮询器的主机必须能访问 BMC 管理网络。当前采集器通过 TCP 443 使用 HTTPS 访问 Redfish，不使用 IPMI 或 UDP 623；IPMI 属于后续阶段。
- 选择有权读取插件所采集资源的账户，不要使用管理员账户。厂商特定角色名称和权限尚未针对真实 BMC 固件验证；请根据 BMC 实际提供的资源验证账户权限。
- 决定轮询器与 Web 服务器读取凭据密钥的方式，以及数据库与密钥共同备份的方法。

<a id="install-and-prepare-the-vault"></a>
## 安装并准备保险库

将插件安装到 Cacti 的 `plugins/redfish` 目录，再通过 Cacti 的 Plugin Management 页面启用。插件检查 PHP 要求，并通过 Cacti 插件 API 创建表。启用后打开 **Configuration → Settings → Redfish**；如果不使用 `/etc/cacti/redfish-vault.key`，请设置保险库密钥路径。

在 Web 根目录外创建 32 字节随机密钥。使用十六进制密钥文件时运行：

```sh
openssl rand -hex 32
```

将输出写入配置路径，并设置权限，允许 Web 服务器与轮询器读取，阻止其他用户读取或替换。所在目录仅允许 root 和拥有密钥的服务账户写入。插件不会创建或修复密钥文件。请将密钥与 Cacti 数据库一起备份；恢复数据库时若没有匹配的密钥，将无法解密已存储密码。

将采集器预算设置为小于 Cacti 轮询间隔。默认采集间隔为 300 秒，采集器预算为 240 秒。未完成的 BMC 会在后续运行处理。重新发现间隔、工作进程数、连接超时、请求超时和响应大小限制应适合管理网络；设置页面给出每项有效范围与默认值。

<a id="configure-tls-and-register-a-bmc"></a>
## 配置 TLS 并注册 BMC

保持证书验证开启。使用私有证书颁发机构时配置 CA 证书包，或固定 BMC 的 SPKI SHA-256 指纹。单个 BMC 的不验证设置会关闭对该 BMC 的对端验证，并在健康页面持续告警；仅可作为隔离管理网络上的临时诊断例外使用。

用只读账户和密码创建凭据项。然后使用 BMC 的 DNS 名称或管理地址、HTTPS 端口、凭据和 TLS 模式添加 BMC。导入文件必须按名称引用凭据，不得含密码。CSV 导入属于管理员操作；导入前请审核数据行和目标地址。

BMC 表单和健康页面显示采集状态及数据年龄。在创建告警阈值之前，应排查认证、TLS、DNS、超时、响应大小和数据过期警告。当前代码尚未针对真实 BMC 固件验证。[research/vendor-matrix.md](../../../research/vendor-matrix.md) 中的厂商矩阵记录已知情况及未验证项目；不要根据模拟 CI 任务推断固件支持情况。

<a id="create-a-device-and-graphs"></a>
## 创建设备和图表

在 BMC 页面选择 **Create Device** 创建独立 Cacti 设备，或选择 **Add Graphs** 将 BMC 查询附加到现有服务器设备。确认前审核计划。插件不会通过 Cacti 设备可用性检查探测 BMC。创建者同时需要 Redfish 管理权限和 Cacti 设备管理权限。创建者无权查看的新设备会回滚。

配置完成后，通过 Cacti 图表创建流程添加 Redfish 汇总和成员图表。BMC 成员变为缺失或消失时，读数为未知（`U`）；插件保留其图表和 RRD 历史。固件更新或组件替换后，再次运行 **Add Graphs** 以重新索引当前成员。只有在不再需要历史记录后才手动移除过时图表。

<a id="configure-alerts"></a>
## 配置告警

Redfish 汇总和成员值都是普通 Cacti 数据源。为站点关心的值创建 Thold 阈值，使用 Maint 计划在预定维护期间抑制通知。阈值持续时间至少设为一个采集间隔，避免对同一缓存读数的重复轮询被视为新观测。如需检测停止响应的 BMC，请保持 `age` 阈值启用。在用于实际运维前，使用您部署的 Thold 和 Maint 版本验证阈值触发与恢复行为。

<a id="back-up-restore-and-handle-failures"></a>
## 备份、恢复和故障处理

将 Cacti 数据库、Cacti 配置、`rra/` 文件和完全匹配的保险库密钥文件作为一套恢复资料备份。密钥备份与数据库备份分开存储，并限制每个副本的访问。在依赖备份之前，先在非生产 Cacti 实例上测试恢复。只恢复数据库或丢失密钥意味着必须重新输入 BMC 密码；恢复数据库而不恢复 RRD 文件会丢失图表历史。

恢复演练时，创建具有相同插件版本的隔离 Cacti 实例，并恢复数据库、Cacti 配置和 `rra/` 文件的副本。修改复制的 Cacti 配置，使其使用恢复数据库的主机和数据库名。启动 Cacti 之前，配置网络规则禁止测试实例访问生产数据库，并确认对生产数据库主机的连接尝试被阻止。仅允许访问恢复的数据库。

在配置路径安装匹配的保险库密钥，保留其所有者与严格权限。连接任何 BMC 之前，使用仅管理员可用的临时 PHP 检查，调用插件的 `CredentialStore::resolve()` 解析一条恢复的凭据。立即丢弃返回的密码，只记录成功或失败，不得输出或记录秘密。插件没有用于这种仅检查凭据的界面操作。然后使用专用于测试的凭据，注册一个隔离实例可访问的专用测试 BMC。保持生产 BMC 地址禁用且无法从测试实例访问；不要将生产凭据发送给测试 BMC。分别记录凭据检查结果和测试 BMC 采集结果。确认采集完成、健康页面报告最新读数，且恢复的图表仍含历史记录。

随后在密钥不可用时重复：采集必须安全地失败，Cacti 页面仍可访问，健康页面必须报告凭据故障。记录 Cacti、PHP、数据库、插件版本及结果，不要将密钥或密码写入报告。这是一套操作步骤，并非已经完成的恢复演练。

如果密钥缺失、不可读或无效，采集会安全地失败；不要换成新密钥并期待旧凭据仍可使用。应恢复匹配的密钥或重新输入凭据。如果 BMC 不可用，插件保留缓存读数并将其标记过期；过期值变为未知而不是零。检查健康页面、轮询日志、DNS、管理网络连通性、账户权限及证书信任。不要为绕过证书问题而全局禁用 TLS 验证。

禁用插件会停止采集。卸载时默认保留插件表。卸载设置可要求删除表；请先导出所需 BMC 和凭据元数据。插件保留 Cacti 设备、图表和 BMC 配置。移除插件不会关闭或重新配置 BMC。

<a id="compatibility-and-qualification-limits"></a>
## 兼容性及验证限制

目前未声明支持任何真实厂商固件系列。开发测试套件包含手写的 Dell、HPE、Lenovo 数据结构和 DMTF 模拟服务器，但这些是测试输入，并非真实设备验证。OpenBMC 及其他厂商系列也需要脱敏采集数据和测试运行后才能声明支持。参阅 [research/vendor-matrix.md](../../../research/vendor-matrix.md) 和议题 [#19](https://github.com/somethingwithproof/plugin_redfish/issues/19)。

插件尚未发布。阶段 1 试点报告、真实 BMC 延迟测量、备份恢复演练及安全验证仍未完成。不能以当前开发构建作为特定 BMC、固件、集群规模或恢复流程已验证的证据。
